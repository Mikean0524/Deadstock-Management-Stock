📌 Executive overview

Retail businesses often retain inventory that is still usable but no longer moving through normal sales channels. This prototype provides a controlled workflow for identifying ageing inventory, verifying its eligibility, and publishing trusted surplus listings.

The central loop is deliberately focused: vendor inventory → ageing/deadstock flag → proof submission → deterministic verification → administrator review where required → verified listing → buyer marketplace.

Only inventory with a VERIFIED verification record can be published to the marketplace.

✨ Key platform capabilities

Inventory lifecycle

Inventory is tracked as ACTIVE, AGING, DEADSTOCK_FLAGGED, or SUBMITTED_FOR_VERIFICATION.

Explainable verification

Required details, proof, quantity, condition, eligibility, and regulated categories produce PASS, REJECT, or MANUAL_REVIEW.

Admin accountability

Regulated or ambiguous inventory reaches an administrator queue for a final approve or reject decision.

Protected publishing

Server-side checks ensure that only VERIFIED inventory becomes a PUBLISHED listing.

🚀 Interactive prototype demonstration

1. Run the full-stack prototype

# Terminal 1 — backend
cd code/backend
npm install
npm run dev

# Terminal 2 — frontend
cd code/frontend
npm install
npm run dev

Open http://localhost:5173. Without a configured DATABASE_URL, the backend runs with its built-in in-memory demo store.

2. Demonstration sequence

  1. Open the marketplace to see a verified public listing.
  2. Sign in as a vendor and add or select an old inventory item.
  3. Submit the deadstock item with proof for verification.
  4. Sign in as an administrator and review the prepared manual-review item.
  5. Approve the item and return to the marketplace.
