Core workflow

From ageing stock to a trusted listing.

The prototype focuses on one practical loop instead of trying to solve every marketplace problem at once.

  1. 01

    Track inventory

    A vendor creates or selects an inventory item. The system calculates its ageing and deadstock status.

  2. 02

    Submit proof

    Eligible deadstock is submitted with a proof image or document for deterministic verification.

  3. 03

    Verify or review

    Rules produce PASS, REJECT, or MANUAL_REVIEW. Regulated or ambiguous items are routed to an administrator.

  4. 04

    Publish verified stock

    Only a VERIFIED item can become a published listing visible in the buyer marketplace.

Prototype scope

Built around accountability, not black-box verification.

The rule engine checks required product information, quantity, condition, proof, deadstock eligibility, and regulated categories. Every outcome is explainable.

System design

One modular system, clear responsibilities.

01

React frontend

Role-aware vendor, administrator, and buyer experiences built with React, TypeScript, Vite, Tailwind CSS, and React Router.

02

Express API

Node.js and TypeScript services provide authentication, inventory lifecycle logic, verification, listings, and marketplace APIs.

03

Data & storage

Prisma models the shared contract for PostgreSQL/Supabase, with Supabase Storage prepared for proof files.
